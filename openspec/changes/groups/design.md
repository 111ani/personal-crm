# Design

## Context

Зачем фича — см. `proposal.md`, что именно должно работать — `specs/contact-groups/spec.md`. Здесь — как сделать.

Что есть сейчас:

- В базе три таблицы: `contacts` (люди), `notes` (заметки), `contact_check_ins` (отметки «Связались»). Заметки и отметки удаляются вместе с контактом (`ON DELETE CASCADE`) — так же будут вести себя связи с группами
- Чтение — в серверных компонентах через `src/lib/contacts/queries.ts`, изменения — через Server Actions (серверные действия) в `src/app/actions.ts`. После любого изменения `refreshAllPages()` обновляет все страницы
- Главная читает строку поиска из адреса (`?q=`); поиск (`search-input.tsx`) заменяет адрес на `/?q=…` и при этом выкидывает из него всё остальное — с группой так нельзя
- Поля контакта (`ContactFields`) общие для окна «Новый контакт» и карточки; частота — отдельное поле только в карточке (`ContactFrequencyField`). Если сохранение не удалось, форма показывает то, что ввели, из ответа сервера (`ContactFormState.values`)
- Окно «Новый контакт» (`AddContactDialog`) — клиентский компонент, его рисует `page.tsx` без данных из базы. Для поля «Группы» ему понадобится список групп с сервера
- Next.js 16 с Cache Components: всё, что читает адрес страницы или базу, стоит в своём `Suspense`. В `AGENTS.md` сказано: перед кодом читать документацию из `node_modules/next/dist/docs/`
- Образ приложения для миграций и тестовых данных копирует из исходников только `src/db/schema.ts` и `src/lib/contacts/frequency.ts` (см. `Dockerfile`). Если `schema.ts` начнёт импортировать новый файл, миграции на сервере упадут
- Автотестов в проекте пока нет. По новому CLAUDE.md — TDD (сначала тест) и Vitest; тесты через браузер (Playwright) и CI будут позже, отдельно

## Goals / Non-Goals

**Goals:**

- Группы и связи «человек — группа» хранятся так, что удаление контакта или группы само убирает связи, а одинаковых названий база не допускает
- Группы человека сохраняются в одном действии с остальными данными контакта: сохранилось всё или ничего
- Список по группе — один запрос к базе, как и сейчас
- По тесту Vitest на каждый сценарий из спеки, на настоящей базе, без риска для локальных данных
- Миграция только добавляет таблицы; откат на прошлую версию приложения работает

**Non-Goals:**

- Тесты через браузер и CI (их настроим позже); тесты на старый код фичи `keep-in-touch`
- Новые библиотеки, кроме Vitest; новые компоненты из шаблонов shadcn
- Менять поведение блока «Пора связаться»

## Decisions

### Что агент решил сам

**1. Две новые таблицы**

- `groups`: `id`, `name`, `created_at`. Уникальный индекс по `lower(name)` — база сама не пустит «Теннис» и «теннис»
- `contact_groups`: `contact_id` → `contacts` и `group_id` → `groups`, обе ссылки с `ON DELETE CASCADE`. Первичный ключ — пара (`contact_id`, `group_id`): один человек не попадёт в одну группу дважды, а группы человека находятся быстро. Отдельный индекс по `group_id` — для фильтра «все люди группы»
- Длина названия (1–50) проверяется в коде (`zod`), как и длина имени контакта; в базе такой проверки нет
- В `schema.ts` для групп ничего не импортируется из новых файлов — иначе пришлось бы менять `Dockerfile` (см. Context)

Альтернативы:

- Список групп текстом в поле `contacts.groups` (например, «Семья, Теннис»). Отказ: переименование и удаление группы пришлось бы делать в каждом контакте, а опечатка создавала бы новую группу
- Расширение Postgres `citext` (текст без учёта регистра). Отказ: нужно включать расширение на сервере, а `lower(name)` делает то же самое без этого
- Отдельное поле с названием в нижнем регистре, которое считает код. Нужно только если Postgres в образе `postgres:18-alpine` не переводит в нижний регистр русские буквы; это проверит первый же тест на одинаковые названия (см. Risks)

**2. Чтение**

В `src/lib/groups/queries.ts`:

- `listGroups()` — все группы по алфавиту с числом людей в каждой; одним запросом (`left join` + `count`). Нужен главной (ряд кнопок), полю «Группы» и странице «Группы»

В `src/lib/contacts/queries.ts`:

- `listContacts(query, groupId?)` и `countContacts(groupId?)` получают необязательную группу: условие «есть связь с этой группой» добавляется к поиску по имени
- `getContactWithNotes(id)` дополнительно возвращает `groupIds` — группы человека, для поля «Группы» в карточке
- `listDueContacts()` не меняется: блок «Пора связаться» на группу не смотрит

**3. Выбранная группа — параметр адреса `?group=<id>`**

- Разбор адреса — маленькая отдельная функция без React и без базы: из `searchParams` и списка групп получает строку поиска и выбранную группу. Если в адресе не `id` или такой группы нет — группа не выбрана («Все»). Блок «Пора связаться» по-прежнему смотрит только на `q`
- Сборка адреса — тоже отдельная функция: `{ q, group }` → `/?group=…&q=…`. Ей пользуются кнопки групп (сохраняют набранный поиск) и поиск (сохраняет выбранную группу)
- Почему адрес, а не память браузера: так работают обновление страницы, «Назад» и закладки, как требует спека, а сервер сразу рисует нужный список

**4. Запись: группы сохраняются вместе с контактом**

- Поле «Группы» отправляет отмеченные группы в форме как несколько значений `groupIds`. `createContact` и `updateContact` читают их (`formData.getAll`), проверяют (`zod`: список `uuid`, без повторов) и в одной транзакции (всё или ничего) сохраняют контакт и заменяют его связи: удалить связи, которых больше нет, добавить новые
- Добавляются связи только с группами, которые есть в базе (вставка через выборку из `groups`). Если группу удалили в другой вкладке, пока была открыта форма, — она молча пропускается, остальное сохраняется
- При ошибке в форме ответ сервера возвращает и отмеченные группы (`ContactFormState.values` дополняется `groupIds`) — отметки не сбрасываются, как и текст в полях

**5. Действия с группами**

В `src/app/actions.ts`, рядом с остальными, все с проверкой `zod` и `refreshAllPages()`:

- `createGroup(name)` — создаёт группу. Если название занято (без учёта регистра), ничего не создаёт и возвращает существующую группу с пометкой «уже была». Страница «Группы» показывает это как ошибку «Группа «Теннис» уже есть», а поле «Группы» просто отмечает существующую — так требует спека
- `renameGroup(id, name)` — переименовывает; занятое название → «Группа «…» уже есть». Переименовать «теннис» в «Теннис» можно: это та же группа
- `deleteGroup(id)` — удаляет; связи уходят сами (`CASCADE`). Уже удалённая группа — не ошибка

Почему создание группы — отдельное действие, а не часть сохранения контакта: «+ Новая группа» должно сразу показать отмеченную метку, а на странице «Группы» контакта нет вовсе. Цена — пустая группа остаётся, если контакт не сохранили (`proposal.md`, «Открытые вопросы», пункт 2).

**6. Экран**

- **Ряд групп на главной** — серверный компонент между строкой поиска и блоком «Пора связаться», в своём `Suspense` без заготовки (если групп нет, ряда нет вовсе — заготовка бы мигала). Кнопки — ссылки (`<Link>`) на адреса из решения 3; выбранная выделена и помечена для экранного диктора (`aria-current`). Ряд переносится на новые строки (`flex-wrap`). В конце — ссылка «Настроить группы» на `/groups`
- **Список** (`contact-list.tsx`) берёт группу из адреса, передаёт её в запросы и пишет счётчик и пустые состояния с названием группы. Тексты собирает отдельная функция в `src/lib/format.ts` — её легко проверить тестом
- **Поиск** (`search-input.tsx`) при замене адреса сохраняет `group` — через функцию сборки адреса
- **Поле «Группы»** — новый клиентский компонент `ContactGroupsField`, один на карточку и окно «Новый контакт». Метки — кнопки (`<button type="button" aria-pressed>`): нажатая выделена и с галочкой. Отмеченные уходят в форму скрытыми полями `groupIds`. «+ Новая группа» открывает строку названия с «Создать» и «Отмена»; у этой строки нет имени поля, поэтому она не отправляется с формой, а Enter в ней создаёт группу, а не отправляет форму. Ответ `createGroup` добавляет метку в список и отмечает её; ошибка — под строкой. В карточке поле стоит после «Почты», перед «Как часто общаться»; в окне — после «Почты»
- **Окно «Новый контакт»**: `page.tsx` рисует кнопку через небольшой серверный компонент, который читает `listGroups()` и передаёт группы в `AddContactDialog`. Пока группы читаются, на месте кнопки — та же кнопка, неактивная
- **Страница «Группы»** — `src/app/groups/page.tsx`: ссылка «Все контакты», форма «Новая группа», список групп. Строка группы — клиентский компонент: название, «4 контакта» / «пока никого», «Переименовать» (поле прямо в строке с «Сохранить» и «Отмена») и «Удалить» (окно подтверждения, как у удаления контакта)
- Вид — как у остальных экранов: те же карточки, кнопки (`Button`) и окна (`Dialog`), только существующие токены. Высота меток — не меньше 44 точек на телефоне, чтобы удобно попадать пальцем. Если понадобится новый цвет или отступ — добавляется в токены, а не прямо в разметку

**7. Тесты — Vitest на настоящей базе**

- Vitest ставится как библиотека для разработки, последней стабильной версии (проверить `pnpm view vitest version` перед установкой). В образ для сервера не попадает: туда ставятся только библиотеки приложения
- Команды: `pnpm test` (прогнать все тесты один раз) и `pnpm test:watch` (перезапускать при правках). Перед ними должна быть запущена база: `pnpm db:up`
- **Отдельная тестовая база.** В том же Postgres в Docker — база с тем же именем, что основная, плюс `_test`. Подготовка перед тестами (`globalSetup`) берёт `DATABASE_URL` из `.env`, меняет имя базы, создаёт её, если нет, и применяет миграции из `drizzle/` тем же способом, что `scripts/migrate.ts`. Перед каждым тестом таблицы тестовой базы очищаются. Защита: если имя базы не кончается на `_test`, тесты отказываются что-либо очищать — так ваши локальные контакты (в том числе ваш собственный) не пострадают. В `.env` ничего добавлять не нужно
- Тесты идут по одному файлу за раз (`fileParallelism: false`): у них одна общая база
- **Что заменяется в тестах.** Только две вещи, которые работают лишь внутри запущенного Next.js: `revalidatePath` из `next/cache` (обновление страниц) — пустышкой, и пакет `server-only` — пустым файлом. База, запросы и проверки — настоящие
- **Тест на каждый сценарий.** Имя теста = название сценария из спеки. Тест делает то же, что делает экран: вызывает те же серверные действия с теми же данными формы и проверяет то, что показала бы страница, — через те же запросы (`listContacts`, `listGroups`, `getContactWithNotes`) и функции текстов и адресов. Что видно только глазами (выделенная кнопка, перенос ряда, «Назад» в браузере) — проверяется руками по сценариям, а позже — Playwright
- Тесты лежат рядом с кодом: `*.test.ts`
- Порядок работы — по CLAUDE.md: сначала тест, запустить и увидеть, что он красный, потом код, тест зелёный

**8. Тестовые данные**

`scripts/seed-data.ts` создаёт шесть групп — «Семья», «Друзья», «Знакомые», «Теннис», «Аналитики», «Работа» — и примерно 60% людей кладёт в одну-две из них; генератор остаётся предсказуемым. `scripts/seed.ts` вставляет группы и связи, а с `--reset` и удаляет их. Список групп — в самом `seed-data.ts` (папка `scripts` копируется в образ целиком). Чтобы увидеть это локально, нужен `pnpm db:seed --reset`, а он стирает локальные данные — перед запуском агент спрашивает разрешения, сохраняет копию базы и возвращает ваш собственный контакт. Проверять сценарии можно и без этого: создать группы руками.

### Мелкие решения по экрану — стоит просмотреть

Их нет в требованиях, агент выбрал сам:

- Ряд групп — кнопки-«пилюли»: выбранная залита фирменным цветом, остальные — с рамкой; «Настроить группы» — ссылка с иконкой шестерёнки, а не кнопка-пилюля
- Метка в поле «Группы» отмечена — залита и с галочкой; не отмечена — с рамкой
- «+ Новая группа» — ссылка-кнопка в конце меток; строка названия появляется под метками
- На странице «Группы» форма «Новая группа» — вверху, над списком
- Удаление группы — красная кнопка в окне подтверждения, как у удаления контакта

### Продуктовые решения, которые ждут вашего подтверждения

Записаны в спеке и перечислены в `proposal.md`, раздел «Открытые вопросы», пункты 1–10: когда сохраняются группы человека, новая группа из поля, правила названия, порядок по алфавиту, когда виден ряд на главной, группа в адресе, добавление контакта при выбранной группе, удаление группы, счётчик на странице «Группы», группы под именем в карточке. ## Risks / Trade-offs

- [Postgres в образе `postgres:18-alpine` может не перевести русские буквы в нижний регистр, и тогда «Теннис» и «теннис» станут двумя группами] → Тест «Такая группа уже есть» гоняется на той же версии Postgres, что на сервере. Если он упадёт — храним название в нижнем регистре отдельным полем, его считает код
- [Пустые группы] «+ Новая группа» создаёт группу сразу, и если контакт потом не сохранили, группа остаётся пустой. → Её видно на странице «Группы» с подписью «пока никого», удаляется в два нажатия
- [Две вкладки с одной карточкой] Сохранение заменяет весь набор групп человека: что сохранили позже, то и останется. → Так же сейчас работают все поля карточки
- [Блок «Пора связаться» не реагирует на группу] Выбрали «Семья», а в блоке — люди не из семьи. → Так решено; блок можно свернуть, а при поиске он скрыт, как раньше
- [Много групп] При 20+ группах ряд на телефоне займёт несколько строк. → Пока принимаем; если станет мешать — сворачивание ряда отдельной доработкой
- [Тесты требуют запущенный Docker] Без базы `pnpm test` падает. → Подготовка тестов пишет понятную ошибку «Запустите базу: pnpm db:up»; README
- [Тесты не проверяют обновление страниц] `revalidatePath` в тестах — пустышка. → Обновление проверяется руками по сценариям, позже — Playwright
- [Окно «Новый контакт» теперь ждёт список групп] → Читается одним быстрым запросом; пока ждёт — кнопка видна, но неактивна

## Migration Plan

- Новая миграция Drizzle (`pnpm db:generate --name groups` → `drizzle/0003_groups.sql`) создаёт таблицы `groups` и `contact_groups` с индексами и ссылками. Существующие таблицы не меняются, данные не трогаются; групп нет, у всех контактов — ни одной группы
- Выкатка обычная: merge в main → образ → миграция отдельным контейнером → новая версия → проверка `/health`. Упала миграция — продолжает работать прежняя версия
- Ручной откат (`rollback.sh`) вернёт прошлую версию приложения; таблицы групп в базе останутся. Прошлая версия о них не знает и работает как раньше. Группы, созданные до отката, сохранятся и снова появятся после следующей выкатки

## Open Questions

- Нужно ли сворачивать ряд групп, если их станет много (20+). Зависит от того, сколько групп будет на деле; на спеку и план сейчас не влияет
