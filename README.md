# Личная CRM

Приложение для своих контактов: кто это, откуда знакомы, телефон и почта, заметки о том, о чём договорились.

## Что умеет

- **Список контактов** — открываете приложение и сразу видите всех людей, по алфавиту
- **Поиск по имени** — начните печатать в строке поиска; слова можно писать в любом порядке: «Смирнова Анна» найдёт «Анна Смирнова»
- **Добавление контакта** — кнопка «Добавить контакт», обязательно только имя. Новый контакт подсвечивается в списке
- **Карточка контакта** — нажмите на человека в списке:
  - слева — заметки: напишите, о чём поговорили, и нажмите «Добавить заметку» (или Ctrl + Enter). Заметки хранятся с датой, новые сверху
  - справа — данные контакта: можно исправить и нажать «Сохранить изменения»
- **Удаление контакта** — в карточке под «Сохранить изменения» кнопка «Удалить контакт». Приложение переспросит; контакт удаляется вместе с заметками навсегда
- Все данные хранятся в базе на сервере, поэтому в любом браузере по тому же адресу видны те же контакты

## Как запустить

Нужны: запущенный **Docker Desktop**, **Node.js** и **pnpm**.

1. Если файла `.env` нет — скопируйте `.env.example` в `.env` и заполните значения
2. Установите зависимости (один раз):

   ```
   pnpm install
   ```

3. Подготовьте базу (один раз): команда запустит PostgreSQL в Docker, создаст таблицы и заполнит базу 1000 тестовых контактов

   ```
   pnpm db:setup
   ```

4. Соберите приложение (заново — после каждого изменения кода):

   ```
   pnpm build
   ```

5. Запустите приложение:

   ```
   pnpm start
   ```

6. Откройте в браузере: http://localhost:3000

Остановить приложение — `Ctrl + C` в окне, где запущен `pnpm start`.

`pnpm dev` — режим разработки: сразу подхватывает правки в коде, но с 1000 контактов список открывается в десятки раз медленнее (около 15 секунд против 0,3). Для обычной работы с контактами используйте `pnpm build` + `pnpm start`.

## База данных

| Команда | Что делает |
| --- | --- |
| `pnpm db:up` | Запускает PostgreSQL в Docker и ждёт, пока база будет готова |
| `pnpm db:migrate` | Создаёт или обновляет таблицы по миграциям из папки `drizzle` |
| `pnpm db:seed` | Заполняет **пустую** базу 1000 тестовых контактов. Если контакты уже есть — ничего не меняет |
| `pnpm db:seed --reset` | **Удаляет все контакты и заметки** и заново заполняет базу тестовыми данными |
| `docker compose ps` | Проверить, что база работает — в колонке STATUS должно быть `healthy` |
| `docker compose stop` | Остановить базу. Данные при этом сохраняются |

Тестовые контакты вымышленные. Почтовые адреса — на зарезервированных доменах `example.com`, `example.org`, `example.net`: такие адреса не принадлежат реальным людям.

## Выкатка на сервер

Приложение работает по адресу https://app.lena-14.ru.

### Как выкатить новую версию

Отправьте изменения в ветку `main` (`git push`). Остальное происходит само, примерно за 3–5 минут:

1. GitHub Actions собирает образ приложения и кладёт его в GitHub Container Registry. Имя образа — `ghcr.io/111ani/personal-crm`, тег — SHA коммита
2. Копирует папку `deploy/` на сервер и запускает `deploy/deploy.sh`
3. На сервере скрипт:
   - скачивает новый образ
   - применяет миграции базы отдельным разовым контейнером. Если миграции упали — новая версия не запускается, работает прежняя
   - запускает новую версию
   - проверяет, что https://app.lena-14.ru/health отвечает 200
   - удаляет старые образы: на сервере остаются только текущий и предыдущий

Ход выкатки виден на GitHub: репозиторий → вкладка **Actions** → workflow **Deploy**. Зелёная галочка — новая версия на сервере. Красный крестик — выкатка упала: откройте запуск и посмотрите, на каком шаге ошибка.

### Если новая версия сломалась: откат

Откат только ручной, сам он не запускается. Он возвращает предыдущую версию приложения; миграции базы при этом не откатываются.

```
ssh crm
sudo -u app-deploy bash /srv/personal-crm/deploy/rollback.sh
```

Повторный запуск той же команды вернёт версию, которая была до отката. Следующий push в `main` выкатит новую версию как обычно.

### Что где лежит на сервере

| Что | Где |
| --- | --- |
| Настройки базы: пользователь, пароль, имя базы | `/srv/personal-crm/.env`, права 600 — читает только владелец |
| Какая версия запущена сейчас и какая была до неё | `/srv/personal-crm/release.env` (пишет `deploy.sh`) |
| Скрипты выкатки | `/srv/personal-crm/deploy/` — копия папки `deploy/`, обновляется при каждой выкатке |
| Контейнеры | Docker, проект `prod`: `prod-db-1` (PostgreSQL, данные в томе `prod_db-data`) и `prod-app-1` (приложение) |
| Настройка nginx для app.lena-14.ru | `/etc/nginx/sites-available/app.lena-14.ru`, образец — `deploy/nginx/app.lena-14.ru.conf` |
| Пользователь, под которым GitHub выкатывает | `app-deploy`: без sudo, может только управлять Docker |

В `.env` на сервере три строки — названия такие же, как в `.env.example`:

```
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=
```

В пароле — только латинские буквы и цифры, например вывод команды `openssl rand -hex 32`.

Для выкатки в настройках репозитория на GitHub (Settings → Secrets and variables → Actions) лежат: секрет `DEPLOY_SSH_KEY` — ключ, которым GitHub входит на сервер; переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` — адрес сервера, пользователь и отпечаток сервера.

Полезные команды на сервере (после `ssh crm`):

| Команда | Что делает |
| --- | --- |
| `sudo docker compose -p prod ps` | Состояние контейнеров: в колонке STATUS должно быть `healthy` |
| `sudo docker logs --tail 100 prod-app-1` | Последние 100 строк логов приложения |
| `sudo cat /srv/personal-crm/release.env` | Какая версия запущена (`APP_TAG`) и какая была до неё (`PREVIOUS_TAG`) |

## Для разработчика

- Next.js 16 (App Router, Cache Components), TypeScript, React 19, Tailwind CSS 4, shadcn/ui (Base UI)
- PostgreSQL 18 в Docker, Drizzle ORM: схема — `src/db/schema.ts`, миграции — `drizzle/`
- Браузер к базе не обращается: чтение — в серверных компонентах (`src/lib/contacts/queries.ts`), изменения — через Server Actions (`src/app/actions.ts`)
- После изменения схемы: `pnpm db:generate` (создаст миграцию), затем `pnpm db:migrate`
- Проверки: `pnpm typecheck`, `pnpm lint`, `pnpm build`
- `/health` — проверка для выкатки: 200, если приложение работает и база отвечает, иначе 503
- Образ — `Dockerfile`; в нём же миграции (`node scripts/migrate.ts`) и тестовые данные (`node scripts/seed.ts`). Выкатка — `.github/workflows/deploy.yml` и `deploy/`
- Требования к фичам ведём в [OpenSpec](https://openspec.dev): действующие требования — `openspec/specs/`, фичи в работе — `openspec/changes/`, настройки (язык спек — русский, контекст проекта) — `openspec/config.yaml`. Команды в Claude Code: `/opsx:propose` — описать фичу, `/opsx:apply` — сделать, `/opsx:archive` — закрыть. На новом компьютере один раз: `npm install -g @fission-ai/openspec@latest`, обновить файлы в проекте — `openspec update`
